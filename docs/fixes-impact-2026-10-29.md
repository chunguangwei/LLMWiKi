# 2026-10-29 修复与影响复核

基线：afb0026 / v0.8.2。本次对应 code-review-2026-10-29.md 的四项发现，并完成独立复核反馈的两项补充修复。本批修复纳入 0.8.3 补丁发布，发布记录见 release-0.8.3.md。

## 修复后的行为

1. 来源面板按项目 ID 与路径隔离状态；目录与摄入缓存共同就绪后才启用批量摄入。请求序号与项目/数据版本检查丢弃过期结果。同项目后台刷新保留文件树，状态加载时禁用摄入，读取失败显示错误并支持重试。
2. 缓存不存在时允许新项目正常使用；已有缓存损坏、读取失败、元数据检查失败均不再作为空缓存。仅来源状态查询启用新的严格存在性检查；其他 fileExists 调用和内部容错缓存保持原语义。
3. 摄入入口校验整批路径后才预解析，拒绝外项目路径及穿越路径。自动监控的相对路径标识保持原样，预解析使用解析后的绝对路径。
4. 任务执行阶段再次检查项目归属，覆盖旧版本持久化队列、后台项目队列及剪藏直接入队。非法任务标记为不可自动重试的失败项，保留可见错误，并释放队列提交顺序锁。兼容项目内的旧相对路径及 Windows/UNC 形式。
5. URL 超时覆盖重定向、响应头和正文读取。响应迟到不会写文件；某条超时仍允许后续 URL 完成。
6. 先检查响应类型和声明长度，再逐块累计字节并解码；超过上限立即取消读取。UTF-8 跨块字符保留完整。重定向和被拒响应的正文也会取消。

## 对现有功能的影响

| 关联路径 | 处理与验证 |
| --- | --- |
| 文件/文件夹导入 | 仍复制到目标项目的 raw/sources，然后进入同一过滤、预解析及摄入队列；原文件不移动 |
| 原始资料自动监控、手动扫描 | 保留相对来源路径，修复了首轮全量回归发现的 5 项兼容性失败；原有测试未改动 |
| 计划导入/后台项目 | 活动项目通过入口校验；后台队列最终执行时统一校验，不要求切换为活动项目后重新导入 |
| 队列恢复、重试与串行提交 | 旧错误绝对路径不会重放；合法旧相对路径继续工作，失败任务不静默丢弃 |
| 来源面板切换/刷新 | 跨项目重置临时状态；同项目加载期间保留可见树，避免刷新闪烁和展开状态丢失 |
| 缓存与 Rust 命令接口 | strict 是可选参数，旧调用继续使用原行为；不修改缓存格式或已有项目文件 |
| URL 导入 | 保留逐条结果、原文保存、唯一文件名和批量入队；改变下载预算的生效时机与超时范围 |
| 模型路由 | 来源按钮订阅提取模型路由及凭证配置变化，使可用性随设置更新 |
| 发布与品牌 | 本次未修改 Logo、签名、更新地址、版本清单或 CI 配置 |

## 验证边界

本轮以组件测试、队列/下载集成测试、原生文件系统测试及构建为依据；未调用真实外部 LLM，未人工安装多平台包。路径校验是针对旧状态串项目的词法归属检查，不提供文件系统符号链接隔离。正文预算限制累计接收内容，不能限制底层传输单个 chunk 的大小及所有 JS 字符串开销。已启动的原项目导入仍可在原项目中完成。
