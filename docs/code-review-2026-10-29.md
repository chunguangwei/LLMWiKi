基线：afb0026（v0.8.2）。本轮审查 Sources UI、来源状态缓存、预处理与入队、项目切换、URL 下载及发布链路。以下为静态调用链确认的缺陷，未通过真实桌面交互复现；不代表全仓库无其他问题。审查阶段未修改业务代码或重新发布；后续修复及发布状态见上方记录。

## P1：项目切换后旧来源可被批量加入新项目

位置：src/components/sources/sources-view.tsx:93、:156、:422。

SourcesView 在 ContentArea 中常驻，项目变化时未清空并绑定来源列表所属项目；loadSources 的异步返回没有项目或请求序号保护。A 切换到 B 后，B 的目录读取完成前，或 A 的旧请求晚于 B 返回时，sources 仍可包含 A 的绝对路径，而 handleIngestAwaiting 使用当前 B 项目。enqueueSourceIngest 只过滤格式及敏感文件，enqueueBatch 只检查项目 ID；队列执行接受绝对路径。因此 B 为活动项目时可以读取 A 的资料并向 B 生成 Wiki。已有任务的项目切换保护不能防止这种错误入队。

建议：列表及摄入状态绑定项目 ID，并丢弃旧请求；未就绪前禁用操作；入队前再验证路径属于目标项目 raw/sources。

## P2：摄入状态未加载或读取失败，被当成全部未摄入

位置：src/components/sources/sources-view.tsx:114、:156、:663；src/lib/ingest-cache.ts:32。

目录与缓存独立异步加载，没有就绪门槛。缓存初始为空，读取失败也返回空条目；此时批量候选函数将所有支持文件当成待处理，按钮可提前开放。已完成文件会重新经历整批预解析与排队。正常内容缓存可能避免后续模型调用，但不能避免这些前置工作；缓存损坏或丢失时还可能重跑模型。

建议：区分加载中、读取成功及读取失败，状态可用后才开放批量操作，失败提供明确反馈。补充目录先返回、缓存晚返回及缓存错误的组件回归。

## P2：URL 超时未覆盖正文下载，可能阻塞整批导入

位置：src/lib/url-source-import.ts:175–188。

60 秒计时器在 fetchImportUrl 返回响应头后即清除，之后 response.arrayBuffer() 没有该超时保护。服务端返回头后持续挂起正文，会卡住当前 URL 及后续串行 URL，并一直保持 importing。Tauri HTTP 插件也使用 ReadableStream 读取正文，此缺陷不仅限于浏览器 fetch。

建议：超时覆盖完整正文读取，在最终 finally 中清理；超时后记录该 URL 错误并继续下一项。

## P2：URL 大小限制在完整缓冲正文之后才生效

位置：src/lib/url-source-import.ts:184–192。

Content-Length 缺失或声明偏小时，arrayBuffer 会先将整个响应载入内存，再检查 maxBytes；不支持的内容类型也在完整读取后才拒绝。大响应可能在大小保护生效前耗尽内存。

建议：提前检查类型，逐块读取并累计字节数，超过限制立即取消流，保留最终长度检查。
